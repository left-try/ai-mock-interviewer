# AI Mock Interviewer

Проект для реалистичной практики собеседований с AI-интервьюером. Сейчас доступны два отдельных сценария: Backend Screening по резюме и System Design с опциональной встроенной доской Excalidraw.

## MVP: готовый локальный контур

Голосовой Backend Screening для уровней Internship, Junior и Middle. Перед интервью кандидат выбирает уровень и загружает резюме, отвечает на вопросы о себе и опыте, а приложение задаёт уточнения по конкретным утверждениям и несостыковкам. После завершения кандидат получает структурированную обратную связь и предварительный вердикт с учётом выбранного уровня.

MVP включает асинхронный сервис с LangGraph, проверку входных данных, парсер PDF/DOCX, контроль переходов и идемпотентности, валидацию структурированных предложений модели и отчёт с проверкой цитат. MCP-сервер связывает сервис с голосовым режимом Codex: модель хоста предлагает следующий ход, граф принимает или отклоняет его. Аудио и отдельный API-модельный ключ приложению не нужны.

См. [инструкцию запуска](docs/GETTING_STARTED.md), [описание MVP](docs/MVP.md), [план тестирования](docs/TEST_PLAN.md), [контракты тестов](docs/TEST_CONTRACTS.md), [проверку голоса](docs/VOICE_PROBE.md) и [backlog](BACKLOG.md).

Для System Design сначала соберите UI: откройте PowerShell в `web/system_design_whiteboard`, выполните `npm ci` и `npm run build`. После перезапуска Codex Desktop запустите skill `system-design-interviewer`; он запросит уровень и явное согласие на наблюдение доски.

## Тесты

Исполняемые контракты находятся в tests/. Установить зависимости: `python -m pip install -e ".[test,voice-probe]"`; запустить: `python -m pytest`. Тесты используют только синтетические данные и поддельную модель, обращений к API нет.

## Принцип расширения

Сценарий интервью задаётся данными: роль, уровень, этап, критерии оценки и доступные инструменты. System Design использует отдельный сервисный контракт и нейтральный `WhiteboardAdapter`; встроенный Excalidraw поставляет нормализованные события. Это позволяет развивать сценарии, не смешивая их с Backend Screening и не привязывая доменную логику к конкретной доске.
