# Запуск Backend Screening MVP

## Первый запуск в Codex Desktop (Windows)

Пользователю нужны Codex Desktop, Python 3.11+ и доступ к этому репозиторию. Отдельный API-ключ для модели не нужен.

1. Клонируйте `https://github.com/left-try/ai-mock-interviewer.git` и откройте папку репозитория в Codex Desktop.
2. В PowerShell из папки репозитория создайте окружение и установите приложение:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -e ".[test,voice-probe]"
   ```

3. Добавьте MCP-сервер в `%USERPROFILE%\.codex\config.toml`. Замените `C:\path\to\ai-mock-interviewer` на полный путь к своей клонированной папке:

   ```toml
   [mcp_servers.interviewer]
   command = "C:\\path\\to\\ai-mock-interviewer\\.venv\\Scripts\\python.exe"
   args = ["tools/voice_probe.py"]
   cwd = "C:\\path\\to\\ai-mock-interviewer"
   ```

   Если `config.toml` уже содержит настройки, добавьте только эту секцию, сохранив остальные параметры.
4. Полностью перезапустите Codex Desktop, чтобы он загрузил MCP-сервер и skill из проекта.
5. Прикрепите резюме PDF/DOCX, включите Voice и запустите `backend-internship-interviewer`. Перед началом выберите Internship, Junior или Middle.

Codex Voice использует подключённые в Codex инструменты и файлы; голосовой режим запускается кнопкой Voice в Desktop. MCP-сервер не может переключить обычный текстовый чат в Voice самостоятельно. [Документация OpenAI по Voice в Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex).

## Как проходит интервью

Обычный сценарий содержит 8–10 ответов кандидата и покрывает мотивацию, образование, проекты, личный вклад, командную работу, сложный случай, выводы и ожидания. После каждого финализированного ответа голосовой хост один раз сохраняет транскрипт в MCP-сессию и только затем задаёт следующий вопрос. По завершении хост сначала вызывает инструмент формирования отчёта, а объявляет интервью завершённым только после подтверждённого успеха. Короткая поправка, дошедшая до сервера до формирования отчёта, сохраняется в ту же сессию; при досрочной остановке непокрытые темы указываются как неопределённость.

1. Прикрепите резюме PDF/DOCX в чат либо вставьте его текстом. Skill использует содержимое вложения, доступное Codex в чате, и передаёт извлечённый текст в `start_interview`. MCP-инструмент принимает текст, а не бинарный файл или путь к нему. Если содержимое файла недоступно Codex, он попросит вставить текст или приложить читаемую копию. Python-сервис также предоставляет `start_from_upload` для передачи байтов PDF/DOCX напрямую.
2. Выберите уровень Internship, Junior или Middle. Codex готовит первый вопрос и передаёт его вместе с резюме и уровнем в `start_interview`.
3. После каждого финализированного ответа Codex вызывает `record_candidate_answer` с точным транскриптом, новым `event_id` и следующим вопросом. Сервер сначала сохраняет ответ, затем проверяет вопрос; повтор события с тем же ID идемпотентен.
4. При достаточном покрытии или просьбе закончить Codex подготавливает отчёт по ответам кандидата и передаёт его в `finish_interview`. Интервью объявляется завершённым только после успешного ответа инструмента. При досрочной остановке в отчёте отмечаются недостающие темы и неопределённость.
5. Резюме и история хранятся в памяти MCP-процесса. Отмена или удаление очищает сессию; при завершении процесса Codex состояние теряется.

После успешного завершения полный отчёт показывается в чате как Markdown, а локально сохраняются два файла: `.md` и `.pdf`. На Windows они создаются в `%LOCALAPPDATA%\ai-mock-interviewer\reports`; путь к обоим файлам возвращается инструментом. PDF использует установленный шрифт с поддержкой кириллицы.

Голос и генерацию текста обеспечивает модель, уже работающая в Codex Voice по подписке. Локальное приложение не подключается к API-модели и не получает сырой аудиопоток: оно хранит финализированный текст и проверяет переходы. Поэтому корректность распознавания и надёжность вызовов инструмента зависят от голосового клиента.

## Тестовый прогон без резюме

Чтобы проверить голосовой сценарий без вложения, включите Voice и запустите `/test-backend-interview`. Выберите уровень Internship, Junior или Middle; будет использован соответствующий вымышленный профиль. До первого вопроса интервьюер предупредит, что распознанные ответы сохраняются в локальный JSONL-журнал. Журналы находятся в `%LOCALAPPDATA%\ai-mock-interviewer\test-runs`, хранятся 30 дней и удаляются инструментом `clear_test_run_logs`.

Сводка локальных измерений запускается командой `python scripts/summarize_test_run.py <путь-к-jsonl>`. Она показывает длительность сохранения ответа, проверки предложения вопроса и отчёта, экспорта Markdown/PDF, полных вызовов MCP и интервалы между вызовами. `client_gap_ms` может включать речь кандидата, распознавание и работу голосового клиента; это не время мышления модели.

## Проверка

```powershell
python -m pytest
```

В наборе есть одна противоречивая фикстура: `test_finish_returns_report_and_marks_session_completed` вызывает `finish` без ответа кандидата, но требует принять доказательство из несуществующего `turn-2` и цитату, которой нет в резюме. Сервис намеренно отклоняет такой отчёт. Остальные контракты должны проходить без изменения тестов; этот fixture/spec конфликт нужно исправить до требования полностью зелёного набора.

Для проверки доступности MCP-инструментов в Codex Desktop откройте новый чат проекта после перезапуска клиента. Для голосовой проверки используйте только вымышленные данные.
