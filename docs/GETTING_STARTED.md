# Запуск Backend Screening MVP

## Первый запуск в Codex Desktop (Windows)

Пользователю нужны Codex Desktop, Python 3.11+ и доступ к этому репозиторию. Отдельный API-ключ для модели не нужен.

1. Клонируйте `https://github.com/left-try/ai-mock-interviewer.git` и откройте папку репозитория в Codex Desktop.
2. В PowerShell из папки репозитория создайте окружение и установите приложение:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -e ".[test,voice-probe]"
   ```

3. Добавьте MCP-сервер в `%USERPROFILE%\.codex\config.toml`. Замените `C:\path\to\ai-mock-interviewer` на полный путь к своей клонированной папке:

   ```toml
   [mcp_servers.interviewer]
   command = "C:\\path\\to\\ai-mock-interviewer\\.venv\\Scripts\\python.exe"
   args = ["tools/voice_probe.py"]
   cwd = "C:\\path\\to\\ai-mock-interviewer"
   ```

   Если `config.toml` уже содержит настройки, добавьте только эту секцию, сохранив остальные параметры.
4. Полностью перезапустите Codex Desktop, чтобы он загрузил MCP-сервер и skill из проекта.
5. В новом чате вызовите `connect_chatgpt_plan` и завершите вход в браузере. Это использует доступ по подписке Codex/ChatGPT; API-ключ и API-биллинг не нужны. Затем вызовите `list_chatgpt_plan_models` и `configure_interview_models`, выбрав быструю модель с минимальным подходящим reasoning для живого диалога и более сильную модель для фонового анализа.
6. Прикрепите резюме PDF/DOCX, включите Voice и запустите `backend-internship-interviewer`. Перед стартом выберите Internship, Junior или Middle.

Codex Voice использует подключённые в Codex инструменты и файлы; голосовой режим запускается кнопкой Voice в Desktop. MCP-сервер не может переключить обычный текстовый чат в Voice самостоятельно. [Документация OpenAI по Voice в Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex).

## Как проходит интервью

Стартовое приветствие и первый вопрос локальные: ожидания модели не задерживают начало беседы. Пока кандидат отвечает, MCP подготавливает модельные маршруты. Каждый финализированный ответ сохраняется до инференса; быстрая подписочная модель выбирает один адаптивный следующий вопрос, а отдельная задача анализирует ответ для будущего отчёта. Голосовой хост начинает одну короткую реакцию на содержание ответа, пока MCP обрабатывает запрос, и после ответа MCP задаёт возвращённый вопрос ровно один раз. Анализ постепенно накапливается в фоне; при завершении остаётся дождаться только незаконченных задач и собрать PDF локально. Интервью покрывает мотивацию, образование, проекты, личный вклад, командную работу, сложный случай, выводы и ожидания. При досрочной остановке пробелы и неполный анализ отражаются в отчёте.

1. Прикрепите резюме PDF/DOCX в чат либо вставьте его текстом. Skill использует содержимое вложения, доступное Codex в чате, и передаёт извлечённый текст в `start_interview`. MCP-инструмент принимает текст, а не бинарный файл или путь к нему. Если содержимое файла недоступно Codex, он попросит вставить текст или приложить читаемую копию. Python-сервис также предоставляет `start_from_upload` для передачи байтов PDF/DOCX напрямую.
2. Выберите уровень Internship, Junior или Middle. `start_interview` получает выбранный уровень вместе с резюме и возвращает локальное приветствие с первым вопросом; не передавайте модели вопрос от хоста.
3. После финализированного ответа хост один раз вызывает `record_candidate_answer` с `session_id`, новым `event_id` и точным транскриптом. Повтор того же события идемпотентен. Не передавайте `next_turn_json` и не вызывайте старые раздельные инструменты.
4. При достаточном покрытии или просьбе закончить вызывается `finish_interview` только с ID сессии. Отчёт строится локально из накопленных фоновых оценок; не передавайте `report_json`. Интервью объявляется завершённым после успешного ответа инструмента.
5. Резюме и история хранятся в памяти MCP-процесса. Отмена или удаление очищает сессию; при завершении процесса Codex состояние теряется.

После успешного завершения полный отчёт показывается в чате как Markdown, а локально сохраняются два файла: `.md` и `.pdf`. На Windows они создаются в `%LOCALAPPDATA%\ai-mock-interviewer\reports`; путь к обоим файлам возвращается инструментом. PDF использует установленный шрифт с поддержкой кириллицы.

Речь распознаёт Codex Voice. MCP получает только финализированный текст и вызывает модели через ChatGPT plan OAuth с подписочными полномочиями; запросы не используют API-ключ и отправляются с `store=false`. Модельные роли и reasoning выбираются по доступному аккаунту. Смена моделей не гарантирует одинаковое время ответа: журнал отдельно показывает настройку маршрута, TTFT/полное время быстрой модели, фоновую оценку и ожидание при завершении.

## Тестовый прогон без резюме

Чтобы проверить голосовой сценарий без вложения, подключите подписку и выберите модели, включите Voice и запустите `/test-backend-interview`. Перед запуском выберите уровень Internship, Junior или Middle; будет использован соответствующий вымышленный профиль. До первого вопроса интервьюер предупредит, что распознанные ответы сохраняются в локальный JSONL-журнал. Журналы находятся в `%LOCALAPPDATA%\ai-mock-interviewer\test-runs`, хранятся 30 дней и удаляются инструментом `clear_test_run_logs`.

Сводка локальных измерений запускается командой `python scripts/summarize_test_run.py <путь-к-jsonl>`. Она различает настройку маршрутов, TTFT и завершение быстрой модели, фоновую оценку, ожидание незаконченных оценок, сборку отчёта и экспорт PDF. `client_gap_ms` может включать речь кандидата, распознавание и работу голосового клиента; это не время мышления модели. Для достоверного сравнения latency нужны повторные голосовые прогоны с тем же аккаунтом, выбранными моделями и сопоставимой длиной ответов.

## Проверка

```powershell
python -m pytest
```

Запустите `python -m pytest`; полный набор проверяет подписочную авторизацию, маршрутизацию, сохранение ответов, фоновую оценку и сборку отчёта с заглушками, без обращения к живой модели.

Для проверки доступности MCP-инструментов в Codex Desktop откройте новый чат проекта после перезапуска клиента. Для голосовой проверки используйте только вымышленные данные.
